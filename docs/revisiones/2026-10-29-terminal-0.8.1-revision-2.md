### 2. P3 — La explicación de `project create --repo` omite la condición para no usar el clon

**Referencia:** `README.md:61–62` y `src/comandos/describir.ts:73`; contraste con `src/repo-local.ts:147–150` y `src/comandos/proyecto.ts:60–91`.

**Qué pasa.** El README dice que `project create --repo` «never reads or writes the clone», y el flag de `describe` promete «without reading or writing this clone's file». Eso sólo es cierto cuando el clon **no corresponde** al repo solicitado. Si corresponde, se conserva la lectura y eventual creación de `.supcoflow/proyecto.json`.

**Escenario concreto.** En un clon reconocido de `Dueno/App`, sin archivo de proyecto, la persona corre `project create --repo Dueno/App` esperando la operación exclusivamente remota que anuncia ese texto. El comando puede crear el archivo local. Con un archivo local incoherente, también puede frenarse por su lectura. La selección del clon es correcta; la promesa absoluta es la imprecisa.

**Arreglo propuesto.** Aclarar en ambos textos: «when this clone is not that repo, creates or reuses the remote project without reading or writing this clone's project file». Mantener el comportamiento actual y, si cambia `describe`, regenerar otra vez su artefacto y la copia de la skill.
