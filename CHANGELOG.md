# Changelog

## Unreleased

Not in the published 0.12.0; it will be in the next release (the number is not decided yet).

- `supcoflow config` shows a project nobody set a data agreement for as `closed (nobody has set it yet)` (the engine marks it `acuerdo_fijado: false`; an older engine's `acuerdo: null` reads the same), never «everything gets through». An answer with no `acuerdo` at all reads `not reported by the engine`. The note on what the agreement covers is now always shown. `install record` records such a project as having no agreement (`null`).
- `describe --json` no longer says the `read` permission covers cases, issues, runs or costs: the terminal has no command to read them.
- **New: `reports list`, `reports show`, `reports investigate`** (stage 2c, the terminal side of «the API of the reports»; they talk to `/api/v1/proyectos/{id}/reportes…` with the key `login` leaves). `reports list [--filter all|needs-you|in-progress|with-issue|saved] [--page n] [--per-page n]` shows the project's reports with their state and whether each needs you; `reports show --id rpt_…` shows one report's journey (events, issue, what can be asked, console link); `--full` adds the rounds of notices to a connected agent and the run. None carries a report's text (the engine doesn't send it). **`reports investigate --id rpt_…` spends**, so it needs `--authorize-spend` and `--ceiling`: without them it sends nothing and exits 4 `falta_autorizacion` with the ceiling and the exact command; if the ceiling changed since it was shown it exits 4 `techo_distinto` and sends nothing; if there is nothing to ask for from there it exits 4 `nada_que_pedir`. The engine's «one investigator per project» rule (409) exits 4 with a fixed phrase. `--dry-run` reads and sends nothing. «Open anyway» and «change the investigator» are not here: they don't exist in the engine yet.
- **New: `gate status`, `gate read`, `gate pass`, `gate deliver`, `gate fail`** (stage 2c: the agent's side of the agents' gate). They use an agent's own key (`scf_ag_…`, created in the console), never the key `login` leaves, and have no `--repo`: the project comes from the key. The key is read from the variable `--from-env NAME` names, from `SUPCOFLOW_AGENT_KEY`, or typed without echo; it is never an argument (`--key` is `flag_desconocido`), is not saved anywhere and is not in any output, even if the engine repeated it. A 401 (exit 2) and a 403 (exit 4) are said clearly, in one request, without trying another credential. `gate status` shows the agent's state; `gate read --id` a report assigned to it and how it ended; `gate pass --id` the five-minute pass (the one thing printed on purpose) and the project's data agreement; `gate deliver --id --file` the result (the delivery id `ent_…` comes from the report and the file, so repeating the same command is the same delivery and never publishes twice); `gate fail --id --file` the closed failure notice (a field outside the contract is rejected by name, not filtered). Engine problems are said as `field:code`, never as values.
- The flags `--filter`, `--page`, and `--per-page` are new; `--id` and `--file` also belong to the new commands, `--from-env` to `gate`, `--full` to `reports list|show` and `gate read`, and `--authorize-spend` / `--ceiling` to `reports investigate`. The error text of a flag used where it doesn't apply names them.
- `taparSecretos` also covers an agent's key (`scf_ag_…`) and a pass (`pse_…`) in any message that comes from outside.

## 0.12.0 (2026-11-17)

It changes an output contract: `diagnose --json` and `test --json` are short by default.

- **Contract change: `diagnose --json` is short by default.** It now prints `{ ok, listo, proyecto, instalacion: { ok, total }, faltan: [{ punto, mensaje, aviso?, siguiente }], siguiente, detalle }` (and, on exit 4, `error: "no_listo"` and `message`). `faltan` lists only the points that are missing; each item of `faltan` carries its own fix in `siguiente`; the top-level `siguiente` is `supcoflow test --json` whenever `listo` is true (even if something such as advice, `aviso: true`, is still missing), and otherwise the fix for the first point that stops a test, in words when it needs data the terminal doesn't have. The text output and the exit codes are unchanged. **Migration:** every field that is no longer in the default output (`puntos`, `instalacion.puntos`, `prueba`, `maquina`, `intento_pendiente`, `politica`, `techo_usd`, `saldo_usd`, `tope_usd`, `comprometido_usd`, `prueba_abierta`) is still there, unchanged, with the new `--full` (`supcoflow diagnose --full --json`), which also adds `siguiente`. `ok`, `error`, `message`, `listo`, `proyecto` and `instalacion.ok` / `instalacion.total` keep their name and meaning in both. A caller that reads the old fields should add `--full`.
- **Contract change: `test --json` without `--authorize-spend` (exit 4 `falta_autorizacion`) and `test --dry-run --json` are short by default.** They now print `{ proyecto, listo, politica, techo_usd, prueba_abierta, maquina: { ok }, detalle }` (`listo` means the same as in `diagnose`: the engine's `listo` and `maquina.ok`; with `--full` it stays the engine's, as before) plus, for `falta_autorizacion`, `error`, `message`, `intento_pendiente` and `siguiente` (fix this machine first; or, when the engine's `listo` is false, run `diagnose` and fix what it says; or else ask the person for the spend and the command to launch it, or, when a request is waiting for confirmation, the command that recovers it), and, for `--dry-run`, `dry_run`, `autorizado`, `intento_pendiente` and `haria`. **Migration:** `puntos`, `saldo_usd`, `tope_usd`, `comprometido_usd` and `maquina.impedimentos` moved behind the new `supcoflow test --full --json` (unchanged there). `--full` with `--wait` or a real `--authorize-spend` exits 3 `flags_incompatibles`. Not shortened: the other commands' JSON is the content they were asked for (`widget`, `config`, `project show`, `agents show`, `guide stale`, `catalog`) or already short (the rest, including `test --authorize-spend` and `test --wait`).
- New `supcoflow describe <command>` (for example `describe diagnose`, `describe repo connect`): describes only that command (`comando`, `flags_globales`, and the exit `codigos` it uses). An unknown name exits 3 `comando_desconocido` and lists the commands. `describe --json` without a command is unchanged.
- The wrong-account message (`dueno_distinto_del_login`) now puts the common case first: the browser's GitHub session is another account; close it (or use a private window), then `supcoflow logout` and `supcoflow login`. The renamed-account hypothesis comes last, and the explanation of `SUPCOFLOW_TOKEN` (it wins over a new login, and `logout` can't remove the variable) stays. The `error`, `motivo` and JSON fields are unchanged.
- The next steps (`siguiente`) of the AI-account, interface and guide points follow the cause in the point's message, not only its name: a model that isn't approved is approved in the Agents tab (the key stays), a check that failed is retried, an interface that needs a newer terminal updates the terminal, and the guide is published from this terminal the first time and with `--from-github` from the main branch afterwards (`guide versions` first). Errors of `test`, `diagnose` and `describe <command>` carry what to do and no unfilled placeholders (`<usd>`, `<policy>`, `prb_…`); an unexplained engine refusal or an unexpected network or engine failure (including one while resolving the project) now adds the next step to its `message` (local failures such as the keychain or the saved-test store keep their own), and a test that needs a person (for example `arranque_incierto`) always says to look at it in the console and not to launch another one, with or without a message from the engine.

## 0.11.1

- `login` and `repo connect` open the approval/connection link in the browser by themselves, in their first step only (never while polling with `--wait`); the link and the code are still shown. Nothing opens without a display, over SSH, in a container or CI, with the new `--no-browser` or with `SUPCOFLOW_NO_BROWSER=1`. With `--json`, the `--start` result adds `navegador_abierto: true|false`.

## 0.11.0

- The guide can be a folder: `.supcoflow/knowledge/*.md` is read as ONE version (every `.md` directly inside it; it governs over `guide.md`/`guia.md` when it has at least one). `guide check` sends the whole set to the engine and prints the problems per document; `guide publish` uploads it, and `--from-github` sends the fingerprint of the whole set (names and contents), computed exactly like the engine's (shared test vectors). A `.md` with an invalid name is rejected by name, never skipped; the limits (64 KB, 60 documents/sections) count for the whole folder.
- `guide check` warns (exit 0) when a section name is repeated (across documents or within one), comparing without case or accents like the chat's search (`nombres_repetidos` in the JSON).
- New `guide stale --base <ref>`: warns, with no AI, no engine call and no sign-in, when a change touches code a document's `sources` explain and doesn't touch that document. It also warns, apart, when the map is empty or broken, when a `sources` pattern matches no file, when a document changed only in whitespace, when the change deletes a document or removes a `sources` pattern that covered code it touches (it reads the map at the merge base too), and when it could not compare or complete the check (missing base, shallow clone, or git couldn't list the repo's files: it suggests `fetch-depth: 0` when that is the cause, and never says «nothing to warn»). Exits 0 unless `--strict` (4 `guia_desactualizada`). README has a CI snippet.

## 0.10.3

- `supcoflow test` and `diagnose` no longer print a «monthly balance» in their text: AI accounts are per project, so a team-wide monthly figure no longer applies. The JSON fields are unchanged.

## 0.10.2

- An `origin` that uses an SSH alias (for example `git@github-gf0:owner/repo`) is now recognized as GitHub. The alias is resolved by reading `~/.ssh/config` as plain text; `ssh` is never run.
- When the home directory is a git repository and git won't let the saved request live there, the warning now suggests a concrete folder outside any repository to use as `XDG_CONFIG_HOME` (on macOS, `/Users/Shared/supcoflow-<uid>`); rerun with it. Where no such folder exists (Linux), nothing is suggested and the usual `git rm --cached` advice stays.
- The saved login, proofs and idempotency files are now refused when their folder sits under a folder others can write to and is not owned by you and private (`0700`, no foreign links). A normal personal folder such as `~/.config/supcoflow` is unaffected, and so is a system without user ids (Windows), which keeps the 0.10.1 behavior.
